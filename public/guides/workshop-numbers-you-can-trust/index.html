The honest answer to "can I trust AI with my numbers?" is: it depends on what you're about to do with them. Spotting a pattern is low stakes. Ordering stock, changing a price or filing taxes is not. The workshop teaches one habit that works at every level: make the tool show how it got the number, then check it against a number from somewhere else.

Question 2

Can I trust AI with my numbers?

Not without checking.

  • AI adds well when it writes a small program to do it (AI-rithmetic, 2026).
  • But it can still add up the wrong rows.
  • In one big test, the best AI finished only about 1 in 3 real spreadsheet jobs (SpreadsheetBench 2, 2026).
  • In another test, the AI added perfectly. But one report had a wrong total. Some AIs noticed. One never did (Ringmod, 2026).

  • Big spreadsheets are still hard. In a test of 321 real business spreadsheet tasks, the best model finished about 1 in 3. On fixing someone else's sheet, it was about 1 in 8 (SpreadsheetBench 2, June 2026).
  • Results change from try to try. On 160 bookkeeping tasks, no model got more than about 3 in 100 right on all 8 tries (APEX-Accounting, July 2026).

Not without checking. AI is now good at doing sums when it runs code, and still unreliable at choosing which rows to add up. That shift matters, because it changes what you check.

Whole workbooks are still hard. SpreadsheetBench 2, an academic test of 321 tasks built from real business spreadsheets, found the best model completed 34.89% of tasks, and as few as 12.00% on debugging someone else's sheet. The authors name the main causes: not inspecting enough of the sheet, and changing the wrong cell (SpreadsheetBench 2, June 2026).

Bookkeeping is hard too, and results vary run to run. APEX-Accounting gave models 160 month-end close tasks written and graded by accounting professionals. The best model met 56.4% of the experts' criteria, and no model got more than 2.6% of tasks right on all 8 of its tries (APEX-Accounting, July 2026). It was built by Mercor with Ramp, two companies that sell evaluation and finance software.

Running code fixes the arithmetic. Google researchers asked frontier models to add long numbers. All of them got worse as the numbers got longer, except Gemini 2.5 Pro with code execution, which usually wrote a short Python script. Its remaining errors came when it didn't use the tool or copied the tool's answer wrongly (AI-rithmetic, February 2026).

But perfect arithmetic doesn't mean a right answer. In an independent test by Ringmod, five top models scored 1,140 numbers with zero arithmetic errors. One source report had a total that was €300 short of its own line items. One model flagged it in 6 of 6 runs; another flagged it in none, and quietly used the wrong total every time (Ringmod, August 2026). The author sells audits, and the test only covers top models at full effort with tools.

Check 1: the till's total. Your till makes its own report, without AI. If the totals differ by even a dollar, stop and find out why.
Check 2: a second way. Work out one number again with a pivot table or SUMIF. For refunds: =SUMIF(M:M,"Refund",I:I).

A second AI isn't enough. Two tools can make the same mistake. Always do Check 1.

Exercise 1: get a clean file (35 minutes)
You find what's wrong with the export before any AI sees it, because a tool that adds up a messy file correctly still gives you a wrong answer.
First, the room adds up the Net sales column the quick way, with SUM. The answer is $11,994.29, almost double the till. Then pairs hunt for the seven traps that explain it.

Every one of these traps is real. Shopify's order export puts each extra item in an order on its own row (Shopify). Lightspeed warns that SKUs over 14 characters or with a leading 0 "are often altered when exported as a CSV file" and suggests exporting XLSX instead (Lightspeed). Toast records a sale when a check is opened, not when it's paid, and its Canadian and US Sales Summary shows net sales, while the UK and Ireland version shows gross sales including VAT (Toast).
Getting the file out of your own till.
  • Square: Dashboard, then Reports, choose the report and filters, then the export icon. Cash drawer reports can't be exported (Square).
  • Shopify: Orders, then Export. More than 50 orders, or an export by date, arrives by email. The export includes customers' names, emails, phones and addresses, so delete those columns first (Shopify).
  • Toast: Sales Summary, then the download icon, as CSV or XLS. The XLS file has several sheets, and a tool that reads only the first one misses the rest (Toast).
  • Lightspeed X-Series: export as XLSX if your SKUs are long or start with 0 (Lightspeed).
Clean-file checklist
  1. Work on a copy. Keep the original export as your record.
  2. Delete customer names, emails, phones and addresses. Replace names with "Customer 1, 2, 3" if you need per-customer counts.
  3. Look for any column of 13 to 19 digit numbers. A full card number or a security code should never be in a file you upload. Under the card industry's PCI DSS standard, security codes must never be stored after a payment is approved, even encrypted (PCI DSS v4.0.1, via PCI Compliance). If you find one, delete the file and ask your payment provider for a clean export.
  4. Delete total, subtotal, title and blank rows.
  5. Remove duplicate rows.
  6. Strip $ signs and commas from amounts.
  7. Fix dates to YYYY-MM-DD.
  8. Write down what each column means: "Net sales is after discounts and refunds, before tax and tips."
In Copilot
Microsoft's new Clean data skill checks for extra spaces, inconsistent formats, duplicates and wrong data types, explains what it finds and proposes fixes you choose to apply. Type @clean-data in your prompt. Microsoft says it is still rolling out (Microsoft, October 27, 2026), so you may not see it yet.
Exercise 2: ask four questions, and make it show its working (40 minutes)
You ask the four questions owners ask most, in one prompt that defines the terms, so the tool can't quietly pick its own definition.
The prompt:
Prompt
I've uploaded two weeks of sales for my café (laneway-coffee-sales-nov-2026.csv). Columns: Date (month first), Order ID, Item, Qty, Net sales, Tax, Tip, Status. Net sales is after discounts and refunds; refunds are negative rows with Status = Refund. Ignore tax and tips. Before you answer, tell me how many rows you read, and list any rows you removed or couldn't read, and why. Then answer one at a time, each with the figure, one line on how you worked it out, and anything that looks wrong:
1. Which items earned the most, by revenue and separately by units sold?
2. Which day of the week is slowest, and which single date? Leave out any day with no sales.
3. How much was refunded in total, in how many rows, and on which item most?
4. What is the average order value? Group lines by Order ID first. Give it with and without refunded orders. Run the calculations in code and show me the code.
In ChatGPT
Attach the file and paste the prompt. When it answers, click the code link at the end of the message to see the Python it ran (OpenAI). If there's no code, the numbers weren't calculated. Then ask: "Which of your four answers are you least sure about, and why?"
In Claude
Turn on Settings, Capabilities, "Code execution and file creation" (in newer layouts it's "Create and edit files") (Claude). Attach the file and paste the prompt, then add: "Give me the result as a downloadable .xlsx with one sheet per question and a sheet listing the rows you removed." Opening the file lets you check the formulas, not just the answer.
In Gemini
Open the file in Google Sheets. If it's an Excel file, save it as a Google Sheets file first. Click Ask Gemini at the top right, paste the prompt, and click "Show code" where it's offered. Insert the answer into the sheet before you close it: Google says the side panel history is lost when you reload or close the spreadsheet (Google).
In Copilot
Format the data as an Excel table first (Ctrl+T) so Copilot sees clear column names. Open Copilot from the icon in the lower-right corner of Excel and pick Plan mode, so it shows its approach and waits for you to confirm, or Chat mode, so it answers without changing the workbook (Microsoft). Ask for the formula it used for each answer.
In Muse
I use Muse, Meta's agent, for research. In this workshop it's useful for one thing: "How do I export a sales report by item from [your till] as CSV?" Check the steps against your till's own help page. The numbers themselves go to a tool that runs code on the file.

You check every answer from Exercise 2 against the key below, then learn three checks that work on your own file without a key. Rereading the answer isn't one of them.

Check 1: the till's own total. Your till makes its own sales report from the same sales, without AI. If AI's total and the till's total differ by even a dollar, stop and find out why. Make sure both cover the same dates and both mean net sales.
Check 2: a second calculation. Get one figure again by a different method: a pivot table, a SUMIF, or filtering the column and reading the total at the bottom of the screen. For refunds: =SUMIF(M:M,"Refund",I:I) in Excel or Sheets, where M is Status and I is Net sales. A pivot table reads the same file, so it catches AI's maths and grouping, not a wrong file. That's why Check 1 comes first.
Check 3: five rows by hand. Pick the two biggest rows, one refund, and two at random. Find each in the till. Most errors sit at the edges: the first and last day, a refund, a split order.
Asking a second AI isn't a check on its own. Two tools can make the same mistake on the same messy file. Use a second tool only as a tripwire, and still do Check 1.
Exercise 4: two tools and an agent (25 minutes)
You build a weekly routine where one tool moves the file, another does the maths, and you check the result before anything is decided. Then you see where an agent fits and where it must stop.
"Monday numbers", the two-tool version.
  1. You (2 minutes). Export last week's sales from your till as CSV and save it in a Google Drive folder called "Weekly sales". This step stays manual on purpose: the till's export is your clean record.
  2. Zapier (automatic). When a new file lands in the folder, add a row to a "Weekly log" sheet with the date and file name. Zapier's free plan costs $0 but allows only two-step Zaps (one trigger, one action), so choose the log row or an email reminder; doing both in one Zap needs a paid plan. Zapier counts a task only when an action succeeds; checking for new files is free (Zapier).
  3. ChatGPT or Claude (5 minutes). Upload the file and paste the Exercise 2 prompt.
  4. You (10 minutes). Check 1, Check 2 on one number, Check 3 on five rows.
  5. You. Save the summary next to the export, named with the week's date.
Zapier can also copy every new Square order into Google Sheets row by row: its own template list includes "Create Google Sheets rows for new Square orders" (Zapier). Each row written is a task, so a busy shop uses up the free plan quickly.
The agent version. An agent can do more of the job on its own. Claude in Chrome, on every paid Claude plan since August 26, 2026, can read pages, click and fill in forms using your logins, which helps with a supplier or bank portal that has no export button. A classifier checks each action against what you asked and blocks anything that doesn't match, and you can turn off auto-approval in settings (Claude). Anthropic also warns that hidden instructions on web pages can try to redirect it, and that "Prompt injection remains a moving target" (same source).
Agents still make costly mistakes. In ShellBench, a test of everyday agent tasks published November 24, 2026, agents recommended duplicate or incorrect invoice payments 40.3% of the time, and 15.7% of attempts failed at least one safety requirement (TechCrunch). The researchers didn't test the consumer versions of these agents, so treat it as a warning, not a score for any product.
Where you approve, always: any payment, any supplier order, any price change, any payroll or tax figure, and anything sent to a customer. The agent may read and draft. You send, pay, order and file.
